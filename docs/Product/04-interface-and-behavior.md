# NIRS Dessert Recipes — интерфейс и поведение

## 1. Назначение документа

Документ описывает структуру экранов и их видимое поведение. Пользовательские пути собраны в [02-users-and-scenarios.md](02-users-and-scenarios.md), проверяемые ожидания — в [03-requirements.md](03-requirements.md), точные алгоритмы — в [05-rules-and-data-meaning.md](05-rules-and-data-meaning.md).

## 2. Структура экранов

Отдельных URL у экранов нет: состояние переключается внутри React-приложения.

| Экран | Доступ | Содержимое |
| --- | --- | --- |
| Чат | Гость и пользователь демо-профиля | Лента, карточки, боковая панель; поле запроса доступно вошедшему пользователю |
| Вход / регистрация | Все посетители | Email, пароль, подтверждение пароля при регистрации |
| Профиль | Пользователь демо-профиля | Имя, смена пароля, удаление демо-аккаунта, выход |
| Окно администратора | Только выделенная демо-учётная запись | Обзор каталога, локальных счётчиков и статуса сервисов; личные данные не отображаются |

Окно открывается после регистрации или входа с выделенными данными, указанными в разделе [«Вход и профиль»](#7-вход-и-профиль). Другие демо-профили переходят в чат. Проверка выполняется в клиентском коде; серверной роли и общей аналитики нет. Целевые ограничения доступа записаны в [правилах](05-rules-and-data-meaning.md#10-правила-входа-и-доступа).

### 2.1. Окно администратора

В разделе «Управление» доступны только «Обзор» и «Вернуться в чат». На обзоре показаны число рецептов в локальном каталоге, локальные демонстрационные счётчики популярных рецептов и состояние подключений. Число общих запросов и пользователей помечено как недоступное: серверной аналитики нет. Демо-администратор может только просматривать эти показатели: ему недоступны чаты, тексты запросов, email, пароли, имена и избранное пользователей; редактирование рецептов и профилей не предусмотрено.

## 3. Экран чата

### 3.1. Боковая панель

| Блок | Содержимое | Действие |
| --- | --- | --- |
| Новый чат | Кнопка создания переписки | Создаёт чат с приветственным сообщением |
| Мои чаты | Название и последнее сообщение | Открывает переписку; доступно удаление чата |
| Избранное | Фото, название, время и тег рецепта | Открывает исходный чат; отдельная кнопка удаляет запись из избранного |
| Популярные десерты | Четыре карточки с наибольшими локальными счётчиками | Создаёт новый чат с полным рецептом; счётчик не меняется |

На узком экране панель закрыта и открывается поверх чата кнопкой меню.

### 3.2. Заголовок и лента

Заголовок показывает название «Чат с Dessert AI», краткое описание и состояние «Просмотр» для гостя или «Демо-режим» для вошедшего пользователя. Название не означает подключение LLM.

Сообщения располагаются сверху вниз. При открытии переписки лента начинается с первого сообщения. После добавления новых сообщений она плавно прокручивается вниз к продолжению чата.

### 3.3. Карточка и полный рецепт

Карточка показывает локальное фото, название, описание, время, сложность и тег. Сердечко добавляет или удаляет рецепт из избранного. Действие «Открыть полный рецепт» добавляет детали в текущую переписку.

Полный рецепт содержит название, описание, локальный счётчик, ингредиенты и нумерованные шаги. Карточка и подробное сообщение используют одну запись рецепта.

### 3.4. Поле запроса

У пользователя демо-профиля внизу чата есть однострочное поле и кнопка отправки; Enter отправляет форму. Ограничение длины и счётчик символов отсутствуют. Гость вместо поля видит блок входа и регистрации.

### 3.5. Результаты запросов

Таблица описывает только видимый результат. Нормализация и расчёт совпадений заданы в [правилах поиска](05-rules-and-data-meaning.md#6-правила-поиска).

| Запрос или действие | Результат в чате | Счётчик |
| --- | --- | --- |
| Точное название основного рецепта | Один полный рецепт | Локально увеличивается на 1 |
| Запрос по ингредиентам, описанию или тегу | Сообщение пользователя, подготовленный локальный текст ответа и не более трёх карточек рецептов | Не меняется |
| Совпадение только с alias | Карточки по ранжированию; полный рецепт не открывается | Не меняется |
| Нет совпадений | Три записи с наибольшими начальными счётчиками | Не меняется |
| Отрицание в запросе или несколько названий | Распознаётся первое точное название; отрицание не учитывается | Может увеличиться для первого рецепта |
| Пустая строка или пробелы | Ничего не добавляется, сообщение не показывается | Не меняется |
| Открытие карточки или популярного десерта | Полный рецепт в текущем или новом чате соответственно | Не меняется |

## 4. Состояния экрана поиска

| Состояние | Что отображается | Статус |
| --- | --- | --- |
| Гость | Пример чата, карточки и вход вместо поля запроса | Есть |
| Новый чат | Приветственное сообщение | Есть |
| Результаты поиска | В ленте видны исходный запрос, текстовый ответ прототипа и не более трёх карточек из локальной библиотеки | Есть |
| Точное название | Запрос и полный рецепт | Есть |
| Продолжение рецепта | Новое сообщение с подробным рецептом в текущем чате | Есть |
| Пустой запрос | Визуально ничего не меняется | Есть; сообщения об ошибке нет |
| Нет совпадений | Показываются три записи по исходной популярности | Есть; пустого результата нет |
| Загрузка | Отдельное состояние отсутствует, поиск синхронный | Не реализовано |
| Сетевая ошибка | Backend и вызов LLM отсутствуют | Не реализовано |

## 5. Действия и переходы

| Действие | Переход или результат |
| --- | --- |
| Войти или зарегистрироваться из гостевого чата | Открывается выбранная вкладка формы |
| Переключить вкладку формы | Меняется набор полей |
| Успешно отправить обычную демо-форму | Открывается чат с локальными данными профиля |
| Отправить вопрос | Вопрос и локальный ответ добавляются в активный чат |
| Открыть полный рецепт | Рецепт добавляется продолжением в тот же чат |
| Нажать сердечко | Рецепт добавляется в избранное или удаляется из него |
| Открыть карточку избранного | Открывается чат, связанный с рецептом |
| Удалить карточку из избранного | Удаляется запись избранного; переписка остаётся |
| Выбрать популярный десерт | Создаётся новый чат с подробностями рецепта |
| Зарегистрироваться или войти с данными администратора | Открывается окно администратора; обычная демо-учётная запись открывает чат |
| Создать или выбрать чат | Создаётся новая переписка или открывается существующая |
| Удалить чат | Переписка удаляется; при удалении последней создаётся пустой чат |
| Открыть профиль | Показывается профиль демо-пользователя |
| Выйти | Локальный вход сбрасывается, открывается гостевой экран |
| Удалить профиль и подтвердить действие | Удаляются локальные данные этого демо-профиля |

## 6. Проверки ввода и валидации

| Форма | Условие | Реакция сейчас | Требование / статус |
| --- | --- | --- | --- |
| Вопрос | Пусто или только пробелы | Отправка прекращается без сообщения | REQ-15 есть; REQ-16 нет |
| Вопрос | Длинный текст | Ограничения и счётчика нет | REQ-17 не реализовано |
| Регистрация | Пустой email или пароль | Показывается ошибка заполнения | REQ-18 частично |
| Email | Формат некорректен | Отправку блокирует проверка поля браузером `type="email"` | REQ-18 частично |
| Регистрация | Пароли различаются | Показывается сообщение об ошибке | REQ-18 есть для этой проверки |
| Регистрация | Email уже сохранён в браузере | Форма сообщает о повторной регистрации | REQ-19 есть |
| Вход | Сохранён неверный пароль | Показывается ошибка входа | Есть |
| Вход | Для email нет сохранённого пароля | Демо-вход всё равно проходит и сохраняет введённый пароль | Ограничение демо |
| Вход или регистрация | Для выделенного аккаунта введён неверный пароль | Показана ошибка; окно администратора не открывается | Есть в демо |
| Профиль | Имя пустое или превышает 32 символа | Пустое значение отклоняется; поле ограничено 32 символами | Есть |
| Профиль | Неверный текущий пароль, новый короче 6 символов или подтверждение различается | Сохранение отменяется с сообщением | Есть в демо-форме |
| Удаление профиля | Пользователь отменяет системное подтверждение | Данные остаются | Есть |

## 7. Вход и профиль

На форме входа есть email и пароль; регистрация дополнительно запрашивает подтверждение пароля. Отдельный демо-аккаунт: `admin@sweetmate.test`, пароль при первой регистрации — `admin123`. Только он открывает окно администратора; обычные демо-аккаунты переходят в чат. Email не подтверждается, серверной сессии нет, пароль сохраняется открытым текстом в `localStorage`. Эти формы предназначены только для демонстрационных данных.

Профиль позволяет изменить отображаемое имя, заменить демо-пароль и удалить локальный профиль. Технические детали хранения и правил входа приведены в [разделе AUTH](05-rules-and-data-meaning.md#10-правила-входа-и-доступа).

## 8. Навигация и доступ

| Кто | Текущее поведение | Целевой доступ |
| --- | --- | --- |
| Гость | Видит пример; не отправляет запрос | Просмотр примера и формы входа |
| Пользователь | Использует чат, свои локальные чаты, избранное и профиль демо-профиля | Доступ к собственной учётной записи и чату |
| Администратор | Выделенная демо-учётная запись открывает окно администратора после входа; проверка выполняется в браузере | В целевой системе доступна только роль `admin` после серверной проверки |

## 10. Адаптивность

В `styles.css` заданы медиазапросы на 980 px и 680 px, минимальная ширина страницы — 320 px. При ширине до 980 px боковая панель выдвигается поверх чата; до 680 px оболочка занимает экран, уменьшаются отступы и упрощается верхняя панель. Отсутствие переполнения на узких экранах вручную не подтверждено; это отмечено в [REQ-32 и REQ-33](03-requirements.md#36-внешний-вид-адаптивность-и-доступность).

## 11. Доступность

В коде есть подписи полей, визуально скрытая подпись вопроса, `aria-label` у части кнопок и `aria-live="polite"` у ленты сообщений. У фото карточек есть альтернативные подписи; декоративные изображения бокового списка имеют пустой `alt`.

Полная проверка клавиатурой и скринридером не проводилась. Системная настройка `prefers-reduced-motion` отдельно не обрабатывается.
