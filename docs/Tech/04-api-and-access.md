# API и доступ

Backend предоставляет HTTP API с префиксом `/api`. Запросы с телом используют JSON. Для изменяющих запросов требуется заголовок `X-SweetMate-Request: 1`. Авторизация выполняется через сессионную cookie.

## Основные маршруты

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/health` | Состояние сервера и настройки сервисов |
| POST | `/auth/register` | Регистрация пользователя |
| POST | `/auth/login` | Вход |
| GET | `/auth/me` | Текущий аккаунт |
| POST | `/auth/logout` | Выход |
| POST | `/demo/login` | Вход в демонстрационный режим |
| PATCH | `/profile` | Изменение имени |
| POST | `/profile/password` | Смена пароля |
| DELETE | `/profile` | Удаление своего аккаунта |
| POST | `/search` | Обработка вопроса с контекстом диалога |
| GET | `/recipes/popular` | Популярные рецепты |
| GET | `/recipes/:id` | Получение рецепта |
| GET | `/admin/stats` | Статистика для администратора |

## Поиск и диалог

`POST /api/search` принимает `query` и необязательные `context` и `history`. Длина вопроса — от 1 до 500 символов.

Ответ содержит текст, до трёх карточек, при необходимости полный рецепт или КБЖУ, обновлённый контекст и статус обработки. Возможные состояния: `found`, `exact`, `clarification` и `empty`. Пустой результат возвращается с HTTP 200, пустым текстом и без новых карточек.

Контекст связывает следующие вопросы с ранее предложенными блюдами. Ингредиенты и исключения проверяются по составу рецептов. Неизвестные значения КБЖУ, времени или порций не заменяются выдуманными данными.

## Авторизация и роли

Пароли хранятся в SQLite в виде хешей scrypt. Сессии используют cookie с `HttpOnly` и `SameSite=Lax`. Обычная регистрация назначает роль `user`; роль `admin` проверяется backend.

Гость не имеет доступа к поисковому API. Пользователь работает со своим аккаунтом. Администратор получает только агрегаты: число запросов, распределение по дням и популярность рецептов. Тексты запросов, чаты и личные данные в административный ответ не включаются.

Демонстрационные аккаунты и статистика изолированы от основной базы. История чатов и избранное сохраняются в браузере, а не в серверных таблицах.

## Ошибки

Ошибки возвращаются в формате `{"message":"Описание ошибки"}`. Основные коды: 400 — неверный ввод, 401 — требуется вход, 403 — нет доступа, 404 — запись не найдена, 409 — email занят, 429 — превышен лимит запросов.

При сбое GigaChat найденные рецепты сохраняются, а интерфейс показывает статус проблемы. Наличие настройки LLM не означает подтверждённую доступность провайдера.
