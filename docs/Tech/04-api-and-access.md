# API и доступ

Все HTTP-маршруты имеют префикс /api.

| Метод и путь | Назначение |
| --- | --- |
| GET /health | Проверка API, индекса и настройки LLM |
| POST /demo/login | Временный тестовый вход |
| POST /auth/register, POST /auth/login | Регистрация и вход |
| GET /auth/me, POST /auth/logout | Текущий аккаунт и выход |
| PATCH /profile | Смена отображаемого имени |
| POST /profile/password | Смена пароля |
| DELETE /profile | Удаление аккаунта |
| GET /admin/stats | Агрегаты для администратора |
| GET /recipes/popular, GET /recipes/{id} | Популярное и карточка рецепта |
| POST /search | Поиск и обработка запроса |

Пароли обычных аккаунтов хешируются scrypt. Сессия создаётся случайным токеном; в SQLite сохраняется его хеш, в браузере используется cookie HttpOnly и SameSite=Lax. Настройка COOKIE_SECURE включает флаг Secure. По умолчанию сессия действует 7 дней.

Обычная регистрация назначает роль user. Администратор настраивается локальными ADMIN_EMAIL и ADMIN_PASSWORD; сервер проверяет роль на защищённом маршруте статистики. DEMO_MODE по умолчанию включает временные тестовые профили в памяти, предназначенные для демонстрации.

Поиск доступен без LLM-ключа. Для GigaChat задай LLM_PROVIDER=gigachat и LLM_API_KEY в локальном .env. Не коммить секреты. При включённой LLM текст запроса передаётся внешнему провайдеру.

POST /search при отсутствии совпадений возвращает `status: empty`, пустой список рецептов и короткое пояснение, которое интерфейс показывает в чате. Явные запросы о несладких блюдах получают ответ о границах SweetMate без карточек десертов. При пустой выдаче LLM не генерирует рецепт.

Backend хранит агрегаты поиска, но не текст вопроса. Реальное развёртывание требует собственной настройки HTTPS, секретов, разрешённых источников и политики хранения.
