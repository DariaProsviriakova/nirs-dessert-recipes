# Архитектура SweetMate

В разработке Vite обслуживает React-клиент на порту 5173 и проксирует /api на Node.js backend на порту 8000. Собранный backend также отдаёт файлы из sweetmate-frontend/dist.

    Браузер → React/Vite → api.ts → Node.js HTTP API
                                      ├─ SQLite: аккаунты, сессии, события
                                      ├─ BM25: локальный корпус и индекс
                                      └─ GigaChat: необязательное пояснение

Основные части:

| Путь | Назначение |
| --- | --- |
| sweetmate-frontend/src/App.tsx | Интерфейс, чаты и клиентское состояние |
| sweetmate-frontend/src/api.ts | HTTP-клиент |
| sweetmate-frontend/src/AdminPanel.tsx | Административная статистика |
| backend/server.mjs | API-маршруты и связывание компонентов |
| backend/auth.mjs, backend/store.mjs | Авторизация и SQLite |
| backend/search.mjs, backend/dialogue.mjs | Поиск и обработка диалога |
| backend/llm.mjs, backend/transport.mjs | Опциональный LLM-провайдер |
| bm25/src/, bm25/scripts/ | Индекс, разбор запроса, подготовка данных и benchmark |

POST /api/search принимает вопрос, backend валидирует его, получает результаты BM25 и возвращает карточки и состояние ответа. При настроенном провайдере LLM может пояснить найденные результаты. Текст запроса в таблицу аналитики не сохраняется; при включённой LLM запрос передаётся внешнему провайдеру.

Аккаунты, серверные сессии и события находятся в SQLite. Демо-сеанс временный. Чаты и избранное хранятся в localStorage и не синхронизируются между устройствами. Сгенерированные данные поиска не коммитятся. Фото загружаются с разрешённых HTTPS-доменов Povarenok, иначе используется заглушка.
