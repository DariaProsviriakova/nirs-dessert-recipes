# Архитектура приложения

SweetMate — веб-приложение для подбора десертов и обсуждения рецептов. Пользователь описывает продукты и пожелания, система находит подходящие рецепты и формирует ответ с помощью GigaChat.

## Общая схема

~~~text
Браузер: React + TypeScript
             │
             │ HTTP API
             ▼
       Backend: Node.js
        ├── Авторизация и роли ── SQLite
        ├── Управление диалогом
        ├── Поиск рецептов ────── каталог и индекс BM25
        └── Генерация ответов ─── GigaChat API
~~~

## Компоненты

| Компонент | Назначение |
| --- | --- |
| Frontend | Чат, карточки рецептов, избранное, профиль и панель администратора |
| Backend | Обработка запросов, контекст диалога, проверка данных и прав доступа |
| BM25 | Поиск по подготовленному корпусу рецептов |
| GigaChat | Интерпретация запросов и формирование разговорных ответов |
| SQLite | Учётные записи, сессии и события для статистики |
| localStorage | История чатов, контекст и избранное в браузере |

## Обработка запроса

1. Frontend отправляет вопрос и контекст текущего чата на backend.
2. Backend определяет действие: поиск, выбор рецепта или уточнение сведений о блюде.
3. Поиск учитывает ингредиенты и ограничения и возвращает до трёх рецептов.
4. GigaChat формирует пояснение на основе найденных данных. КБЖУ и пересчёт порций обрабатываются backend по сведениям источника.
5. Результат возвращается в чат, а контекст сохраняется для следующих вопросов.

Если совпадений нет, новые карточки и сообщение ассистента не добавляются. При недоступности LLM найденные данные остаются доступны.

## Доступ и хранение

Гость просматривает пример. Пользователь работает с чатом, избранным и профилем. Администратор видит агрегированную статистику без текстов запросов и личных данных пользователей. Права проверяются сервером.

Демонстрационные аккаунты используют отдельное временное хранилище. Обычные аккаунты сохраняются в локальной SQLite, история чатов — в браузере. Синхронизация истории между устройствами не предусмотрена.

Рецепты загружаются из подготовленного индекса. Фотографии основного каталога отображаются по URL источника; стартовые демо-изображения находятся во frontend.
