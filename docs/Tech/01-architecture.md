# Архитектура SweetMate

Обновлено 2026-11-25. Локальная интеграция, без публикации.

Браузер передаёт вопрос, контекст текущего чата и до шести предыдущих сообщений. Сервер проверяет сессию, входные ограничения и ID рецептов.
backend/dialogue.mjs определяет сценарий: подбор, выбор блюда, сравнение, КБЖУ, порции или общение.
Частые действия распознаются непосредственно, для остальных при наличии ключа вызывается интерпретатор GigaChat.

## Поиск и данные

Готовый BM25 загружается один раз. backend/catalog.mjs формирует в памяти десертное подмножество: 27 664 из 28 768 записей.
Это эвристика, не ручная проверка. Исходные файлы, веса и разметка bm25/ не меняются; статистика индекса в памяти относится к подмножеству.
backend/search.mjs ранжирует и проверяет все названные продукты по составу каждой записи. Дополнительные продукты разрешены и обозначаются.
Для обычного подбора выше ставятся записи с известными порциями и калорийностью, затем используется балл BM25.
Для сравнения сортировка числовая, по выбранной единой базе; неизвестные значения исключаются.
Однозначное основное название открывает полный рецепт; неоднозначное предлагает выбор.

backend/recipe-data.mjs проверяет пищевую ценность, сопоставляет названия ингредиентов, масштабирует количества и готовит карточку.
Нулевые целиком КБЖУ считаются отсутствующими. Пересчёт возможен только при известных исходных порциях.
Шаги остаются исходными, количественные изменения показываются в составе с предупреждением о шагах.

## GigaChat

backend/llm.mjs использует OAuth, кеш токена и GigaChat-2. backend/transport.mjs добавляет официальный CA только в HTTPS-клиент LLM, TLS не отключается.
Для разговора модель получает вопрос, контекст, ограниченную историю и найденные записи; email, профиль, ключ и токены не передаются.
Для пояснений передаются предыдущие пользовательские сообщения, чтобы прежний ошибочный ответ модели не закреплял неверные цифры.
Рецепты отображаются из корпуса. Сравнение, КБЖУ и пересчёт порций сервер объясняет непосредственно, без генерации чисел моделью.
Из прочих ответов удаляются предложения с числовыми КБЖУ. Полная семантическая проверка любого свободного текста не заявляется.
Сбой или отсутствие ключа сохраняет серверные данные и пояснение. Старый explain/проверка фактов оставлен для совместимости, текущий HTTP-диалог использует interpret/reply.

## Сервер и хранение

Node.js 24: HTTP, crypto, SQLite. backend/server.mjs — маршруты, доступ, ограничение частоты, события и статика.
backend/auth.mjs — scrypt, сессии и роли; backend/store.mjs — аккаунты, сессии и агрегаты; backend/config.mjs — локальные настройки.
SQLite не хранит переписку. Чаты, контекст и избранное остаются в localStorage по accountId. Старые демо-данные не мигрируются.
React раздаётся тем же сервером на localhost:8000; Vite на 5173 проксирует API в разработке.

## Разговорные вопросы по выбранному блюду

Диалог поддерживает discuss: вопросы о размере порции и открытые уточнения рецепта получают данные текущего блюда и свободный ответ GigaChat.
Это отдельный ответ, без новых карточек и запуска поиска.
При неизвестном весе модель получает это ограничение явно; сервер проверяет числовые веса в ответе и дополняет пояснение об отсутствии данных.
При невыбранном блюде pendingRecipeQuestion сохраняет вопрос до уточнения «у первого/второго».
Проверка не гарантирует достоверность любого свободного кулинарного совета; данные источника остаются первичными.

Если в источнике отсутствуют шаги, вопрос «почему/зачем нужно…» не должен подтверждать предположенный пользователем обязательный этап; ответ сообщает об отсутствии инструкций.

## Память всего чата

backend/recipe-memory.mjs проверяет и разрешает ссылки по всем известным ID, названиям, номерам блюд и подборкам.
Frontend восстанавливает память из всех сообщений текущего чата и передаёт компактные ID, не все полные тексты рецептов.
Сервер повторно читает нужный источник; память не зависит от ограничения LLM-истории шестью сообщениями.
knownRecipeIds и recipeGroups не отправляются целиком во внешний LLM: модель получает выбранное блюдо, а поиск ссылки выполняется локально.
Новые чаты имеют независимую память. Открытие карточки и числовые вопросы не заменяют подборки.
Хранение остаётся в текущем браузере, синхронизации и неограниченной ёмкости localStorage не заявляется.
