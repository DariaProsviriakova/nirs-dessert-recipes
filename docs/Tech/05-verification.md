# Проверка проекта

Из корня, Node.js 24:

~~~bash
npm test
npm run build
npx playwright install chromium
npm run test:e2e
~~~

npm test проверяет настоящий HTTP API с SQLite в памяти, поиск на небольшом контролируемом корпусе,
проверки оснований LLM-ответа и обмен GigaChat OAuth/completions с имитацией сети.
npm run test:e2e поднимает собранный сайт на 127.0.0.1:8011, использует полный локальный BM25 и отдельную
базу со случайным именем в backend/.test-artifacts/. Рабочая база и пользовательский .env не используются.
Запуск браузерных тестов требует подготовленного индекса и production-сборки.

Проверяемые браузерные сценарии: гостевой доступ и неизменность старых ключей, регистрация, запрос с ограничениями,
карточки, источник и полный рецепт, избранное и чаты после перезагрузки, имя, пароль, выход, удаление только синтетического аккаунта,
пустая выдача, уточнение КБЖУ, обрыв сети, админ-панель и мобильный экран 360 px.

Результаты и скриншоты сохраняются в backend/.test-artifacts/, исключены из Git.
Playwright trace сохраняется при ошибке.

## Ручной маршрут

1. Откройте localhost:8000: гость не может отправлять вопросы.
2. Зарегистрируйте синтетический аккаунт; запросите «банан до 30 минут без сахара».
3. Откройте рецепт, проверьте ингредиенты, шаги и ссылку на источник; сохраните в избранное и перезагрузите страницу.
4. Введите «ксдфжщы» — пустой результат; «банан до 200 ккал» — уточнение базы.
5. Проверьте профиль, новое имя и смену пароля. Выход должен закрывать доступ к API.
6. Войдите администратором из локального .env. Проверьте агрегаты и отсутствие личных данных.
7. После настройки GigaChat проверьте живой ответ, неверный ключ и временное отключение сети.

Живой GigaChat-2 проверен 2026-11-25 через сайт с локальным ключом и SQLite в памяти. Успешная сборка и автоматические тесты не подтверждают качество всех рецептов, всех ограничений естественного языка или полную доступность со скринридером.

Дополнительно проверяются точный запрос «у меня есть печенье, яйца, молоко, овощи» на полном индексе,
исключение киша/хачапури, сохранение настоящих десертов с яйцами и маслом и доступность composer после нескольких ответов на широком экране.
Актуальный результат: 56 серверных тестов и 11 браузерных сценариев.

Живая проверка: OAuth 200, completion 200, llmStatus=ok; в Chromium отображаются ответ и три карточки.
Новая TLS-проверка сертификата, отказ от HTTP и сохранение обычного fetch без CA покрыты транспортными тестами.

## Диалоговый маршрут

В одном новом чате отправляйте по очереди:

1. «У меня есть банан и молоко. Что можно приготовить?» — каждая карточка содержит оба продукта; остальные перечислены отдельно.
2. «Где меньше калорий?» — новый порядок по возрастанию ккал/100 г; текст совпадает с карточками.
3. «Выбираю первый» — полный рецепт первого варианта.
4. «Покажи КБЖУ этого блюда» — четыре показателя именно выбранного блюда, база на 100 г.
5. «На 6 человек» — новые количества при известных исходных порциях; ккал/100 г не меняются.
6. «А без молока» — новый подбор с бананом без молока, включая исключение сгущёнки.
7. «У меня есть мука и орехи и молоко» — новый список заменяет прежние продукты/исключения; каждая карточка содержит все три.

Живой маршрут пройден с GigaChat-2 и SQLite в памяти; ошибки страницы отсутствуют.
Сравнение, КБЖУ и порции имеют llmStatus=not_needed: числа формирует сервер, это штатный ответ.
Нулевые целиком КБЖУ источника считаются отсутствующими. Без исходных порций система просит выбрать другой рецепт.
При неоднозначном вопросе о КБЖУ система уточняет блюдо; при невозможном сочетании продуктов не подставляет случайные карточки.
Генеративный текст не гарантирует понимание любых формулировок. Все числовые факты проверяются отдельно.

После изменения кода перезапустите npm start в своём терминале, обновите страницу Ctrl+F5. Старые сообщения не меняются.
