# Запуск SweetMate в VS Code

Проверенная среда: WSL Ubuntu 24.04, Node.js 24.22.3.
Команды npm выполняются из корня **nirs-dessert-recipes**, рядом с корневым package.json.
Интеграция находится в проверочной ветке backend/gigachat-chat-integration. В main эти изменения ещё не объединены.

## 1. Что установить

- Git и VS Code.
- Node.js **24.x** с npm. Версия проекта записана в .nvmrc.
- Для проверенного варианта на Windows: WSL Ubuntu и расширение WSL для VS Code.
- Интернет для установки пакетов, первого скачивания корпуса и общения с GigaChat.

Node.js: [официальная установка](https://nodejs.org/en/download/).
Python, Docker, PostgreSQL, отдельный сервер SQLite и локальная установка нейросети не нужны.
SQLite входит в Node.js, GigaChat вызывается по внешнему API.

## 2. Получить и открыть проект

Для нового участника — получить сразу проверочную ветку:

~~~bash
git clone --branch backend/gigachat-chat-integration --single-branch https://github.com/DariaProsviriakova/nirs-dessert-recipes.git
cd nirs-dessert-recipes
~~~

Если папка уже существует, повторно клонировать её не нужно. Сохраните свои локальные изменения, затем:

~~~bash
git fetch origin
git switch --track origin/backend/gigachat-chat-integration
~~~

Если локальная ветка уже создана, вместо второй команды выполните git switch backend/gigachat-chat-integration.
Не используйте reset --hard и не удаляйте свой .env ради переключения ветки.
В VS Code выберите «Файл → Открыть папку» и откройте **корень репозитория**, не только sweetmate-frontend.
Откройте «Терминал → Создать терминал».

Для WSL папка и терминал должны быть открыты в Ubuntu.
На текущем устройстве путь такой; у других участников он будет своим:

~~~bash
cd /home/uawei_d/NIRS/nirs-dessert-recipes
source ~/.nvm/nvm.sh
nvm install
nvm use
~~~

Команды source/nvm относятся к уже установленному nvm в Ubuntu.
Если nvm ещё не установлен, установите Node.js 24 по официальной инструкции.
Для Windows без WSL используйте Node.js 24 для Windows и PowerShell в корне проекта; команды source/nvm из Ubuntu пропустите.
Нативный Windows-запуск в этом протоколе не проверялся; рекомендуемый проверенный путь на Windows — WSL.

Проверьте в том же терминале:

~~~bash
node --version
npm --version
~~~

Ожидается v24.x.x. Ошибка bad option: --env-file-if-exists=.env обычно означает старую выбранную версию Node.

## 3. Установить зависимости

Один раз после получения проекта, затем при изменении lock-файлов:

~~~bash
npm ci
npm --prefix sweetmate-frontend ci
~~~

Первый пакет содержит инструменты проекта и тестирования; второй — React, TypeScript и Vite.
Зависимости BM25 устанавливает следующий шаг. Создавать новые package.json через npm init не нужно.

## 4. Подготовить корпус и индекс

На новой установке:

~~~bash
npm run prepare:data
~~~

Команда устанавливает зависимости bm25, скачивает Parquet-датасет d0rj/povarenok_recipes_detail с Hugging Face,
формирует корпус и BM25-индекс. Это подготовка поиска, а не обучение GigaChat.

Скачивание зависит от сети и доступности Hugging Face. На текущем устройстве raw и generated вместе занимают около 324 МБ;
зависимости и Chromium требуют место отдельно.

После успешного завершения должны существовать:

~~~text
bm25/data/generated/dessert-corpus.jsonl
bm25/data/generated/corpus-stats.json
bm25/data/generated/bm25-index.json.gz
~~~

Эти файлы не передаются через Git — каждый участник создаёт их у себя.
Размер корпуса может зависеть от версии внешнего датасета.
Перед каждым запуском повторять prepare:data не нужно. На текущем устройстве индекс уже подготовлен.

Если скачивание оборвалось, восстановите доступ к Hugging Face и повторите команду.
Parquet-файлы с правильным размером повторно не загружаются, корпус и индекс пересобираются.
Для исправления индекса не очищайте рабочую базу backend/.data.

## 5. Создать личный .env

.env находится **в корне рядом с package.json**, не внутри backend/frontend.
Он может быть приглушён в проводнике VS Code: Git игнорирует файл, но сервер его читает.
На текущем устройстве .env и ключ уже настроены — не заменяйте файл.

Для первого создания в Ubuntu/Bash:

~~~bash
if [ ! -e .env ]; then cp .env.example .env; fi
~~~

Для первого создания в Windows PowerShell:

~~~powershell
if (-not (Test-Path -LiteralPath .env)) { Copy-Item -LiteralPath .env.example -Destination .env }
~~~

Откройте .env в редакторе. У каждого участника собственный файл.
.env.example — общий образец без секретов. Сам .env не добавляется в Git и не выводится в общие логи.

### Без GigaChat

В .env:

~~~dotenv
LLM_PROVIDER=none
LLM_API_KEY=
~~~

Работают вход, поиск, карточки, источник, КБЖУ, известное время и математический пересчёт.
Ответы используют серверные пояснения; свободное общение GigaChat без ключа недоступно.

### С GigaChat

1. Откройте developers.sber.ru и войдите в личный кабинет.
2. Создайте/откройте проект GigaChat API для физического лица.
3. Перейдите в настройки API / данные авторизации.
4. Скопируйте **Authorization Key**. Нужен готовый авторизационный ключ, а не только Client ID и не access token.
5. Вставьте свой ключ в LLM_API_KEY в личном .env.

[Официальный быстрый старт](https://developers.sber.ru/docs/ru/gigachat/individuals-quickstart),
[авторизация](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/gigachat-api).

~~~dotenv
LLM_PROVIDER=gigachat
LLM_API_KEY=ВСТАВЬТЕ_СВОЙ_AUTHORIZATION_KEY
LLM_MODEL=GigaChat-2
LLM_BASE_URL=https://api.giga.chat/v1
GIGACHAT_AUTH_URL=https://ngw.devices.sberbank.ru:9443/api/v2/oauth
GIGACHAT_SCOPE=GIGACHAT_API_PERS
LLM_CA_FILE=backend/certs/russian_trusted_root_ca.pem
LLM_TIMEOUT_MS=20000
~~~

Замените текст ВСТАВЬТЕ_СВОЙ_AUTHORIZATION_KEY настоящим значением.
Не добавляйте Basic, Bearer или название переменной в само значение ключа.
Сервер самостоятельно получает и обновляет access token.
Модель должна быть доступна вашему проекту; при другой доступной модели измените LLM_MODEL.
Внешний API требует действующего доступа и доступного лимита токенов.

Публичный CA уже входит в исходники и подключается только HTTPS-клиентом LLM.
Для этого серверного клиента не требуется вручную устанавливать сертификат в браузер.
Проверку TLS не отключайте. Ключ не передаётся во frontend: используйте LLM_API_KEY, не VITE_*.
После изменения .env остановите сервер Ctrl+C и запустите npm start заново.

### Администратор — необязательно

Обычный аккаунт создаётся через регистрацию на сайте.
Для первого администратора укажите свои данные в .env:

~~~dotenv
ADMIN_EMAIL=ваш_административный_email
ADMIN_PASSWORD=ваш_пароль_не_короче_6_символов
~~~

Если оба поля пусты, администратор автоматически не создаётся; обычная регистрация работает.
Редактирование этих полей не меняет пароль или роль существующего аккаунта.
Не используйте синтетические пароли из автоматических тестов как свои рабочие.

## 6. Собрать и запустить

~~~bash
npm run build
npm start
~~~

При успехе терминал пишет:

~~~text
SweetMate: http://localhost:8000
~~~

Терминал остаётся занят процессом — это нормально.
Откройте http://localhost:8000. Один процесс обслуживает API и собранный интерфейс.
Для обычного запуска второй терминал не нужен.
Не открывайте dist/index.html отдельным файлом и не используйте Live Server.

Сначала виден гостевой пример. Зарегистрируйтесь или войдите для отправки собственных вопросов.
SQLite backend/.data/sweetmate.sqlite создаётся автоматически, импортировать чужую базу не требуется.
Она хранит аккаунты/сессии/статистику, а рецепты читаются из отдельного BM25-индекса.

Откройте http://localhost:8000/api/health: ожидается status=ok и search=ready.
llm=configured подтверждает только наличие настройки, а не успешный запрос к модели.

## 7. Проверить диалог

В одном чате по очереди:

1. «У меня есть банан и молоко. Что можно приготовить?» — оба продукта есть в карточках, дополнительные перечислены отдельно.
2. «Где меньше калорий?» — новый порядок по одной базе КБЖУ.
3. «Выбираю первый» — полный рецепт.
4. «Сколько калорий?» — ответ по выбранному блюду без случайных карточек.
5. «Насколько большая порция?» — число порций и отсутствие неизвестного веса.
6. «Сколько по времени готовить?» — время источника или сообщение об отсутствии.
7. «На 6 человек» — пересчёт при известных исходных порциях.
8. «Есть мука и орехи и молоко» — новый подбор.
9. «Сколько времени занимает второе блюдо из первой подборки?» — возврат к раннему блюду.
10. Обновите страницу и спросите о раннем блюде по названию — память сохраняется.

В некоторых исходных записях нет времени, КБЖУ, порций или шагов: сообщение об отсутствии данных является корректным результатом.
При нескольких невыбранных блюдах помощник уточняет выбор. Старые сообщения не переписываются после обновления программы.

Проверка именно живого GigaChat: F12 → Network → POST /api/search → Response.
У разговорного ответа модели llmStatus=ok. not_needed у серверного числового ответа — штатное состояние.
not_configured — нет настроенного ключа/провайдера; unavailable — внешний вызов не удался; invalid_response — ответ модели не принят.
Наличие карточек и HTTP 200 сами по себе не доказывают работу внешней модели.

## 8. Ежедневный запуск на текущем устройстве

В терминале WSL:

~~~bash
cd /home/uawei_d/NIRS/nirs-dessert-recipes
source ~/.nvm/nvm.sh
nvm use
npm start
~~~

npm ci и prepare:data ежедневно не нужны.
После изменения frontend выполните npm run build и Ctrl+F5 в браузере.
После изменения backend/.env перезапустите сервер через Ctrl+C и npm start.
Если изменились обе части, выполните оба действия.

Процесс, запущенный инструментом Codex, не появляется в вашем терминале VS Code.
Для видимого процесса запускайте команды в собственном терминале. Не запускайте несколько серверов на порту 8000.

## 9. Режим разработки — необязательно

Терминал 1, корень:

~~~bash
npm run dev
~~~

Терминал 2, корень:

~~~bash
npm --prefix sweetmate-frontend run dev -- --host 127.0.0.1
~~~

Сайт: http://localhost:5173.
Vite обновляет frontend, Node --watch перезапускает backend при изменении импортируемого кода.
.env требует ручного перезапуска. API-прокси Vite рассчитан на порт 8000.
Этот режим заменяет npm start; оба одновременно не запускайте.

## 10. Автоматические проверки

Серверные тесты без настоящего ключа:

~~~bash
npm test
~~~

Типы и production-сборка:

~~~bash
npm run build
~~~

Браузерные тесты после подготовки индекса и сборки:

~~~bash
npx playwright install chromium
npm run test:e2e
~~~

Если Ubuntu сообщает о недостающих системных библиотеках Chromium:

~~~bash
npx playwright install --with-deps chromium
~~~

Последняя команда может потребовать права администратора для системных пакетов.
Она нужна только для браузерных тестов, не для обычного открытия сайта.

Последний проверенный набор: 56 серверных тестов и 11 браузерных сценариев.
Обычные тесты используют имитацию LLM, синтетические аккаунты и отдельные базы; рабочая база не очищается.
Сервер браузерных тестов занимает порт 8011 и завершается после проверки.
Артефакты сохраняются в backend/.test-artifacts и не входят в Git.
Обычные автоматические тесты не расходуют GigaChat-ключ; ручные живые запросы расходуют доступный лимит модели.

## 11. Типичные проблемы

| Симптом | Что делать |
| --- | --- |
| bad option: --env-file-if-exists=.env | Проверьте node --version в том же терминале; в WSL выполните source ~/.nvm/nvm.sh и nvm use. |
| nvm: command not found | Linux-команда не работает в PowerShell. В WSL загрузите установленный nvm через source либо установите Node.js 24 по официальной инструкции. |
| ENOENT package.json | Перейдите в корень nirs-dessert-recipes, а не backend или frontend. |
| Cannot find package / vite not found / tsc not found | npm ci и npm --prefix sweetmate-frontend ci; для BM25 — npm --prefix bm25 ci. |
| BM25 index unavailable | npm run prepare:data; проверьте INDEX_PATH и наличие bm25-index.json.gz. |
| Dataset Viewer / download failed | Проверьте сеть и доступ к Hugging Face, повторите подготовку. На новой установке нужен доступ к этому внешнему источнику. |
| EADDRINUSE: 127.0.0.1:8000 | Порт занят. Найдите свой предыдущий сервер и остановите Ctrl+C в его терминале, затем запустите одну копию. |
| После правки старый интерфейс | npm run build, затем Ctrl+F5. Старые ответы в истории останутся прежними. |
| После правки старое поведение backend | Остановите старый процесс Ctrl+C и выполните npm start из того же корня. |
| Карточки есть, свободного ответа нет | Проверьте LLM_PROVIDER, личный Authorization Key, scope, модель, лимит и сеть; перезапустите сервер. configured в health не проверяет модель. |
| Ошибка TLS у GigaChat | Проверьте путь LLM_CA_FILE и публичный сертификат из репозитория. Не отключайте TLS. |
| На другом компьютере нет моего аккаунта | У локальных запусков разные SQLite. Зарегистрируйтесь заново; чаты/избранное тоже не синхронизируются. |
| Нет КБЖУ/времени/порций/шагов | Поле может отсутствовать в источнике; это не обязательно ошибка запуска. |
| Playwright: executable doesn't exist | npx playwright install chromium. |
| Playwright не стартует на 8011 | Проверьте, что предыдущий тестовый сервер завершён и порт свободен. |

Посмотреть порт в WSL без остановки процесса:

~~~bash
ss -ltnp 'sport = :8000'
~~~

В PowerShell:

~~~powershell
Get-NetTCPConnection -LocalPort 8000 -State Listen | Select-Object LocalAddress, LocalPort, OwningProcess
~~~

Если нужен другой порт обычного запуска, измените PORT и APP_ORIGINS в .env.
Например: PORT=8001 и APP_ORIGINS=http://localhost:8001,http://127.0.0.1:8001.
Перезапустите сервер и откройте http://localhost:8001.
Для Vite-разработки также изменяется API-прокси на новый порт.

## 12. Что общее, а что личное

Через Git передаются исходники, тесты, lock-файлы, .env.example, документация и публичный сертификат.
Локально остаются .env, ключи, рабочая SQLite, node_modules, собранный frontend, корпус/индекс и результаты тестов.
Каждый участник создаёт их по этой инструкции.
Состав будущей отправки: [06-release-files.md](06-release-files.md).

Обычный запуск предназначен для локального устройства.
Публичный хостинг и общая серверная база для команды этой инструкцией не настраиваются.

## 13. Как проверена эта инструкция

Шаги установки проверены в изолированной WSL-копии без личного .env, рабочей базы, node_modules и готового индекса.
Зависимости установлены из локального npm-кеша; Parquet-файлы взяты из существующего кеша, поэтому полная повторная загрузка датасета не выполнялась.
Корпус и индекс пересобраны, 56 серверных тестов и 11 браузерных сценариев прошли, сборка успешна.
С .env из образца без ключа проверен npm start на отдельном свободном порту: сайт, health, регистрация и поиск работают.
Проверка не затрагивала рабочую базу и сервер пользователя. Официальные страницы Node.js и авторизации GigaChat сверены 2026-11-25.
