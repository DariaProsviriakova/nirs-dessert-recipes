# Запуск приложения

Нужны Node.js 24, npm и подготовленный индекс рецептов. Команды выполняются из корня репозитория. В WSL с установленным nvm версия Node выбирается командой `nvm use`.

## Подготовка

~~~bash
npm ci
npm --prefix sweetmate-frontend ci
npm run prepare:data
~~~

Создайте в корне файл `.env` на основе `.env.example`. Существующий файл с настройками не перезаписывайте.

Для GigaChat заполните `LLM_API_KEY` ключом авторизации и оставьте параметры провайдера из шаблона. Ключ используется только backend. Без LLM можно запустить поиск с `LLM_PROVIDER=none`.

## Запуск

~~~bash
npm run build
npm start
~~~

Сайт доступен по адресу `http://localhost:8000`. Сервер работает в текущем терминале; остановка — `Ctrl+C`. После изменения `.env` или backend сервер нужно перезапустить. После изменения frontend повторите сборку и обновите страницу.

## Режимы доступа

- Гостевой режим доступен без входа.
- Обычный аккаунт создаётся через регистрацию.
- Демо-пользователь и демо-администратор доступны через кнопки тестового входа.
- Настоящий администратор создаётся на старте из `ADMIN_EMAIL` и `ADMIN_PASSWORD`, если указанный email ещё не зарегистрирован.

У каждого локального запуска своя база. Демо-данные сервера сбрасываются после его перезапуска.

## Проверки

~~~bash
npm test
npx playwright install chromium
npm run test:e2e
~~~

Серверные и браузерные тесты используют отдельные тестовые данные. Для браузерных проверок нужна собранная версия frontend и свободный порт 8011.

## Локальные файлы

`.env`, база `backend/.data/`, скачанный датасет и сгенерированный индекс не входят в Git. Каждый участник создаёт свои настройки и выполняет `npm run prepare:data`. При обновлении подготовки корпуса индекс нужно пересобрать.

Ошибка `EADDRINUSE` означает занятый порт: остановите ранее запущенный экземпляр сервера. Ошибка отсутствия индекса требует повторной подготовки данных.
