# Учебный benchmark RAG/BM25 — занятие 3

Этот набор добавлен отдельно от основного benchmark каталога: он точно соответствует формату задания и не заменяет оценку поиска по большому корпусу.

## Состав

Файл bm25/data/course-benchmark.json содержит фиксированные 30 рецептов из датасета Povarenok с ID D01–D30 и сохранёнными исходными ID. В нём есть 15 запросов: 10 с ответом и 5 ловушек без подходящего ответа. У каждого обычного вопроса не менее трёх gold-документов. Релевантность для обычных вопросов размечена по составу: указанный ингредиент должен быть прямо в списке ингредиентов рецепта.

Основной benchmark в bm25/data/benchmark.json остаётся отдельным набором для развития поиска: 20 ручных и 10 field-derived запросов по полному корпусу. Его метрики нельзя смешивать с учебным набором из 30 документов.

## Запуск

Из корня проекта:

~~~powershell
cd bm25
npm ci
npm run benchmark:course
~~~

Команда сохраняет выдачу и ответы в bm25/data/course-benchmark-results.json. Если нужно получить ответы настроенной GigaChat, запусти:

~~~powershell
npm run benchmark:course -- --with-llm
~~~

В этом режиме команда читает настройки из корневого .env, не выводит секреты и вызывает LLM только для вопросов, по которым есть найденные карточки. Для ловушек ответ формирует backend без передачи рецептов модели. Без --with-llm в отчёт попадает безопасный ответ backend без генерации моделью.

## Метрики и ограничения

- Recall@5 и MRR@10 считаются по 10 обычным вопросам на BM25 top-10.
- Answer Accuracy считается по показанным карточкам: ответ верен, если есть хотя бы одна карточка и все показанные карточки входят в gold-набор запроса.
- Correct Rejection Rate считается по пяти ловушкам: верный отказ означает пустой список карточек и непустое пояснение.
- Отчёт сохраняет текст ответа, найденные ID, заголовки и ссылки на источники для каждого из 15 вопросов.

Последний прогон без LLM дал Recall@5 81,8%, MRR@10 1,000, Answer Accuracy карточек 100% (10/10) и Correct Rejection Rate 100% (5/5). Это baseline фиксированного мини-набора, его нельзя сравнивать с метриками полного корпуса.

Answer Accuracy в отчёте проверяет релевантность карточек, а не смысл каждого предложения свободного текста. Если запускался режим с LLM, перед сдачей отдельно прочитай сохранённые ответы и вручную проверь их опору на рецепты. Пустая выдача не передаёт найденные документы модели.

Чтобы пересоздать фиксированный срез после обновления полного корпуса, из корня проекта выполни npm run prepare:data, затем из bm25 — npm run benchmark:course:prepare. После пересборки проверь goldDocIds; если включить этот JSON в коммит, учебный benchmark будет запускаться в клоне без скачивания полного датасета.
