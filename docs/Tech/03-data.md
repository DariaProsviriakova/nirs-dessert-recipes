# Данные и хранение

## Корпус рецептов

Источник — [d0rj/povarenok_recipes_detail](https://huggingface.co/datasets/d0rj/povarenok_recipes_detail). Скрипты скачивают train Parquet и эвристически отбирают рецепты-кандидаты; весь набор вручную не проверен.

- bm25/data/raw/ — Parquet-источники.
- bm25/data/generated/ — нормализованный корпус и сжатый индекс.
- bm25/data/benchmark-results/ — локальные результаты benchmark полного корпуса.
- bm25/data/manual-aliases.json и manual-benchmark-queries.json — ручные материалы, хранящиеся в Git.
- bm25/data/course-benchmark.json и course-benchmark-results.json — отдельные статические JSON-файлы учебного набора из 30 документов и отчёта.

Сырые Parquet и полный сгенерированный корпус исключены из Git. Для рабочего приложения на новом клоне выполни npm run prepare:data. Учебный набор запускается отдельно; см. [06-bm25-and-benchmark.md](06-bm25-and-benchmark.md) и [07-course-rag-benchmark.md](07-course-rag-benchmark.md).

Запись рецепта может включать источник, категории, описание, ингредиенты, шаги, время, порции, КБЖУ и URL изображения. Фотофайлы не скачиваются: используются URL Povarenok с локальной заглушкой, если подходящей ссылки нет.

## Хранение приложения

SQLite по умолчанию находится в backend/.data/sweetmate.sqlite:

| Таблица | Данные |
| --- | --- |
| accounts | Email, имя, хеш пароля, роль, дата создания |
| sessions | Хеш токена и срок действия |
| events | ID аккаунта/сессии, время, статус и длительность поиска |
| result_recipes | ID рецептов в результате поиска |

Текст поискового запроса в этих таблицах не сохраняется. Старые события и сессии очищаются по настройке ANALYTICS_DAYS, по умолчанию — 90 дней. Тестовые демо-пространства используют SQLite в памяти и исчезают после остановки процесса.

Чаты и избранное остаются в localStorage данного браузера и не синхронизируются. Когда включён GigaChat, для разбора неоднозначного запроса провайдер может получить вопрос и часть контекста переписки (до шести последних сообщений). Если поиск нашёл рецепты и требуется пояснение, вместе с вопросом и контекстом провайдер получает данные только найденных карточек, не весь каталог. При пустой выдаче документы рецептов не передаются; вопрос и контекст могут передаваться только на этапе определения намерения.
