# Данные и хранение

## Рецепты

Готовый модуль bm25/ создаёт корпус dessert-corpus.jsonl и bm25-index.json.gz в bm25/data/generated/.
Локально собрано 28 768 рецептов из d0rj/povarenok_recipes_detail. Скрипты, настройки ранжирования и ручная разметка сохранены без изменений.

backend/search.mjs преобразует запись корпуса в карточку: id, title, description, ingredients, steps, time, tag, sourceUrl, nutrition, servings.
Без фотографий используется собственная SVG-заглушка; сложность не выводится как известная.
Пропущенные время, шаги, порции и КБЖУ не восстанавливаются догадками.
Ссылка ведёт к источнику Поварёнок; наличие источника не означает ручную проверку рецепта или прав на его текст.

## SQLite

Файл по умолчанию: backend/.data/sweetmate.sqlite, режим WAL.
- accounts: id, нормализованный уникальный email, display_name, scrypt-хеш пароля, серверная role, created_at.
- sessions: SHA-256-хеш случайного токена, account_id, expires_at.
- events: eventId, accountId, хеш идентификатора сессии, queryId, submittedAt, resultStatus, durationMs.
- result_recipes: уникальные пары eventId/recipeId для подсчёта популярности.

Полный текст запроса и переписки в SQLite не записываются. При удалении аккаунта сессии удаляются, события обезличиваются.
Истёкшие сессии и события старше ANALYTICS_DAYS очищаются при запуске, поиске и чтении статистики.
Аналитика имеет явно указанный период и группирует даты по UTC.

## Браузер

Чаты: sweetmate:v2:chats:<accountId>. Избранное: sweetmate:v2:favorites:<accountId>.
Карточки и сообщения хранятся в текущем браузере, синхронизации между устройствами нет.
Старые sweetmate:* ключи демо-версии остаются нетронутыми и не предоставляют доступ к новому API.
После выхода данные чатов остаются; удаление своего аккаунта через интерфейс удаляет его v2-данные в текущем браузере.

## Граница каталога сайта

Корпус на диске остаётся исходным (28 768 записей).
Сайт использует серверное подмножество 27 664 рецептов после отсева явно несладких названий и ингредиентов.
Проверяются корневая категория, признаки сладких блюд и несладкой начинки; сливочное масло само по себе не считается сладкой начинкой.
Яйцо куриное и сливочное масло не исключают десерт. Киш, хачапури, мясная/овощная закусочная выпечка не выдаются.
Это эвристическая защита границы приложения, а не изменение работы участницы по RAG или ручная разметка корпуса.

## Контекст и расчёты диалога

Контекст хранится в сообщении локального чата: продукты, исключения, фильтры, показанные ID, выбранное блюдо, желаемые порции.
На сервер передаётся только ограниченная история, данные источника повторно загружаются по проверенным ID.
КБЖУ на 100 г и на порцию сохраняются при масштабировании; на всё блюдо умножаются на коэффициент порций.
Если на порцию отсутствуют, но известны КБЖУ всего блюда и исходные порции, значение вычисляется делением.
Отсутствующие количества не додумываются; нулевые целиком показатели источника считаются неизвестными.

## Память всех блюд чата

Контекст версии 3 содержит knownRecipeIds и recipeGroups. Он хранится с локальными сообщениями, но не в SQLite-аналитике.
При старых сообщениях без этих полей frontend восстанавливает память по карточкам, полным рецептам и объектам КБЖУ.
После нового подбора прежние ID сохраняются; source lookup проверяет каждый ID независимо от клиентского снимка.
