# Аудит датасета Povarenok recipes detail

Дата проверки: 2026-11-24.

## Краткий вывод

d0rj/povarenok_recipes_detail подходит как **кандидат на исходный корпус для русского BM25-прототипа**: у записей есть названия, категории, ингредиенты, шаги, время, порции и вложенная пищевая ценность. Но это общий каталог рецептов, а не готовая коллекция десертов. Перед построением индекса нужно выделить десертные категории и отдельно измерить полноту нутриентов на этой выборке.

Время приготовления заполнено у 103 369 из 154 158 записей (67,05%), порции — у 87 922 (57,03%). Число десертных записей и полнота поля пищевой ценности в агрегированной статистике не определились. Для времени обнаружены 107 записей со значениями более 24 часов — их нужно проверить, а не автоматически принимать или удалять.

## Состав и размер

По [карточке датасета](https://huggingface.co/datasets/d0rj/povarenok_recipes_detail) и её [README со схемой](https://huggingface.co/datasets/d0rj/povarenok_recipes_detail/blob/main/README.md):

- один split train, 154 158 строк;
- 19 полей, язык помечен как русский;
- файл для скачивания занимает около 200 МБ; размер после распаковки по метаданным — около 634 МБ;
- карточка описывает набор как подробную выгрузку рецептов с Povarenok.ru.

Основные поля:

| Поле | Содержание |
| --- | --- |
| title, description | Название и описание |
| page_url, main_image_url | Ссылка на исходную страницу и URL основного изображения |
| kroshki | Категории рецепта в виде списка |
| ingredients | Список ингредиентов с названием и исходным количеством |
| cooking_time, portions_count | Время и число порций, оба значения хранятся строками |
| cooking_steps | Упорядоченные шаги |
| purposes, tags, tastes | Дополнительные метки |
| nae_value | Вложенные значения белков, жиров, углеводов и ккал |
| cooking_steps_images_urls, cooking_additional_images_urls, user_photos_urls, recipe_variants_urls | Ссылки на изображения и варианты рецептов |

В nae_value заявлены три основы: «100 г блюда», «Готового блюда» и «Порции». Для каждой указаны carb, fats, kcal, protein. Это удобно для будущих фильтров по КБЖУ, но нельзя смешивать значения с разной основой. Агрегированный endpoint статистики не вернул покрытие вложенного поля nae_value, поэтому процент заполнения нужно посчитать после загрузки и фильтрации десертной выборки.

## Проверенная полнота и качество полей

Агрегаты получены через [Hugging Face Dataset Viewer Statistics API](https://datasets-server.huggingface.co/statistics?dataset=d0rj%2Fpovarenok_recipes_detail&config=default&split=train); доли рассчитаны от 154 158 строк.

| Поле | Наблюдение | Что учесть |

| description | 5 пропусков | Можно индексировать вместе с названием, ингредиентами и метками |
| kroshki | 1–4 категории на строку, среднее 2,83 | Категория нужна для отбора десертов; весь датасет не является десертным |
| ingredients | 0–46 элементов, среднее 8,98, медиана 9 | Есть пустые списки; отдельные количества ингредиентов могут отсутствовать |
| cooking_steps | 0–124 элементов, среднее 8,02, медиана 7 | Есть пустые списки; проверять пригодность записи для ответа с инструкциями |
| cooking_time | 50 789 пропусков (32,95%); 103 369 значений (67,05%), 249 уникальных строковых значений | Все непустые значения в агрегированной частотной таблице распознаются как целое число минут; 107 строк превышают 1 440 минут |
| portions_count | 66 236 пропусков (42,97%); 87 922 значения (57,03%), 102 уникальные строки | Перед числовыми фильтрами нужно нормализовать и проверить выбросы |
| nae_value | Вложенная структура с тремя основами КБЖУ присутствует в схеме и в примере строки | Покрытие по всему набору и по десертам пока не измерено |

Первой строкой в просмотрщике оказались бутерброды «Кораблики с икрой» с категорией «Закуски». Это подтверждает, что нужен отдельный фильтр десертов. Точное количество таких строк не приводится: во время аудита поиск Dataset Viewer вернул HTTP 503, а простая статистика API не считает элементы внутри списка kroshki.

## Лицензия и происхождение

На странице Hugging Face указана лицензия apache-2.0. При этом карточка называет набор выгрузкой с Povarenok.ru (source_datasets: crawled) и помечена WIP. В карточке не описано отдельно, как лицензия датасета соотносится с правами авторов исходных рецептов и фотографий. Поэтому для проекта нужно сохранить page_url, не включать фотографии в BM25-корпус и отдельно проверить условия использования исходного сайта и материалов перед публикацией корпуса или приложения.

## Решение для нашей части

**Можно продолжать с этим датасетом для учебного локального прототипа BM25**, если сначала сформировать отдельный корпус десертов и сохранить исходные поля для прослеживаемости. Выбор пока не означает, что весь дамп готов к индексации или что его можно публиковать без проверки источника.

## Следующие действия

1. Загрузить исходный Parquet локально, не добавляя большой исходный файл в Git.
2. Отобрать десерты по kroshki, проверить названия категорий и вручную просмотреть небольшую случайную выборку.
3. На десертной выборке посчитать точные количества и пропуски для cooking_time, portions_count и каждого основания nae_value.
4. Подготовить нормализованные поля, сохраняя исходные значения: time_minutes, servings, КБЖУ на 100 г и на порцию. Выбрать явное правило для пустых, неоднозначных и экстремальных значений.
5. Сформировать текст документа для BM25 из названия, категорий, описания, ингредиентов и меток; оставить URL источника для проверки рецепта.
6. Собрать небольшой benchmark запросов и ожидаемых ID рецептов; оценивать Recall@k и MRR отдельно от корректности рецептов и КБЖУ.
