# Решения и вопросы

Файл фиксирует принятые решения и вопросы, по которым решение ещё не принято. Пока вопрос открыт, документы опираются на указанное рабочее допущение. После решения вопрос переносится в раздел «Принято», а затронутые документы обновляются; изменение записывается в [`../../CHANGE_HISTORY.md`](../../CHANGE_HISTORY.md).

Ответственные назначены по зонам работы, указанным в [README проекта](../../README.md); это не меняет распределение обязанностей команды.

## Актуальная локальная интеграция — 2026-11-25

Решения D-02–D-04 ниже описывают исторический frontend-прототип и заменены D-06–D-10 в текущей локальной версии.

| ID | Дата | Решение |
| --- | --- | --- |
| D-06 | 2026-11-25 | Backend на Node.js 24 напрямую импортирует существующий JavaScript BM25. SQLite хранит аккаунты, сессии и аналитические события. |
| D-07 | 2026-11-25 | Чаты и избранное остаются в браузере под новыми ключами с accountId; старые демо-данные не мигрируются и не удаляются. |
| D-08 | 2026-11-25 | По выбору пользователя используется GigaChat. Модель получает только вопрос и найденные записи, сервер проверяет ID и дословные основания ответа. |
| D-09 | 2026-11-25 | Сессии непрозрачные, хранятся на сервере в хешированном виде; cookie HttpOnly. Обычная регистрация не назначает администратора. |
| D-10 | 2026-11-25 | Без ключа или при ошибке LLM поиск и карточки остаются доступны. Изображения корпуса не загружаются; используется собственная заглушка. |

GAP-02 и GAP-03: для интеграции используются уже готовые поля и алгоритм BM25 из bm25/README.md, а не старый локальный скоринг.
GAP-04: провайдер выбран пользователем — GigaChat; живой доступ подтверждён с локальным ключом.
GAP-05: реализованы агрегаты запросов, дней и популярности. Рабочие сроки 7 дней для сессий и 90 дней для событий настраиваются; утверждение политики командой остаётся открытым.
GAP-01 и GAP-06: источник корпуса известен, но ручная проверка каждой записи и права на публикацию не подтверждены.

## 2026-11-25: диалог и числовая достоверность

По запросу пользователя согласована интеграция контекста и необходимых изменений frontend при сохранении его функций.
Свободный текст модели в живой проверке путал победителя сравнения и числовые базы КБЖУ.
Решение: свободное общение и распознавание намерений — GigaChat; числовые ответы, состав, шаги и масштабирование — серверные данные.
Подбор требует всех названных продуктов; дополнительные ингредиенты видны явно. Изменения RAG ограничены адаптером сервера, исходный bm25/ не редактируется.
