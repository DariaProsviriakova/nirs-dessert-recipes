# Backend SweetMate

Node.js 24; команды выполняются из корня репозитория.

~~~bash
npm run build
npm start
~~~

- config.mjs — настройки и пути.
- store.mjs — SQLite-схема, очистка сроков хранения и агрегаты.
- auth.mjs — валидация, scrypt, cookie и серверные сессии.
- catalog.mjs — серверная граница десертного каталога, без изменения корпуса и BM25.
- search.mjs — адаптер готового BM25 к карточкам и полному рецепту.
- transport.mjs — HTTPS-клиент LLM с дополнительным CA, без изменения системного доверия.
- certs/russian_trusted_root_ca.pem и certs/README.md — публичный официальный сертификат и его происхождение.
- tests/transport.test.mjs — сертификат, запрет HTTP и обычный транспорт без CA.
- llm.mjs — GigaChat OAuth, распознавание намерений и разговорное пояснение.
- server.mjs — HTTP API, права, события поиска и раздача собранного сайта.
- tests/helpers.mjs — контролируемый корпус и временный HTTP-стенд.
- tests/api.test.mjs — API, аккаунты, роли, сессии, аналитика и ошибки.
- tests/catalog.test.mjs — отсев несладких блюд, сохранение десертов с яйцами/маслом и распознавание списка продуктов.
- tests/search-llm.test.mjs — ограничения поиска, проверка цитат, GigaChat с имитацией сети.
- tests/browser/site.spec.mjs — реальные браузерные сценарии с полным индексом и отдельной тестовой базой.

Подробнее: [архитектура](../docs/Tech/01-architecture.md), [запуск и ключ](../docs/Tech/02-running.md),
[API](../docs/Tech/04-api-and-access.md), [проверки](../docs/Tech/05-verification.md).

Настройки: .env.example → локальный .env. GigaChat API-ключ в frontend не передаётся.
Без ключа остаются поиск и серверные пояснения; свободное общение недоступно. Тесты не используют рабочий .env или рабочую базу.

~~~bash
npm test
npm run test:e2e
~~~

## Остальные новые файлы интеграции

- Корневой package.json — команды запуска, сборки и тестов; package-lock.json — зафиксированные npm-зависимости.
- .nvmrc — Node.js 24.
- .gitignore — исключение секретов, рабочих/тестовых баз и артефактов.
- .env.example — безопасный образец настроек; локальный .env — настройки устройства и случайный пароль администратора, с пользовательским ключом только на этом устройстве.
- playwright.config.mjs — браузерный стенд на порту 8011 с отдельной тестовой базой.
- sweetmate-frontend/src/api.ts — запросы к серверу и понятные ошибки.
- sweetmate-frontend/src/AdminPanel.tsx — административные агрегаты и автообновление.
- sweetmate-frontend/public/images/recipe-placeholder.svg — собственная нейтральная заглушка фотографии.

Сгенерированные локальные файлы: bm25/data/raw/ (датасет), bm25/data/generated/ (корпус, статистика, индекс),
backend/.data/ (новая рабочая SQLite), backend/.test-artifacts/ (отдельные тестовые SQLite, скриншоты и трассировки).
Эти данные не коммитятся. Предыдущих рабочих баз в проекте не было.

Уже существующие App.tsx, styles.css и vite.config.ts изменены для подключения API и состояний;
документы Product/Service/Tech, README, STATUS, CHANGE_HISTORY и AGENTS синхронизированы с локальной реализацией.

2026-11-25: живой GigaChat-2 и полный путь через сайт проверены; ключ остаётся только в локальном .env.

## Файлы диалоговой интеграции

- dialogue.mjs — контекст беседы, выбор сценария, исключения, сравнение, КБЖУ и порции; серверные числовые пояснения.
- recipe-data.mjs — проверка исходных КБЖУ, сопоставление продуктов, дробные количества и масштабирование карточек.
- tests/dialogue.test.mjs — продолжения диалога и защита числовых ответов от противоречивого текста модели.
- tests/browser/site.spec.mjs — дополнительно цепочка подбор → калории → выбор → КБЖУ → 6 порций и проверка всех продуктов в карточках.

Из исходного frontend сохранены чат и история, избранное, популярное, профиль, регистрация/вход/выход, меню и адаптивность.
App.tsx дополнен примером вопроса, передачей контекста, составом карточек и таблицей КБЖУ.

В dialogue.mjs добавлен discuss: отдельные ответы GigaChat на вопросы по выбранному рецепту, включая размер порции; неизвестный вес не подменяется базой КБЖУ.

- recipe-memory.mjs — память всех блюд чата, порядок подборок и разрешение ссылок по названию/номеру.
- tests/recipe-memory.test.mjs — проверка ID, старых подборок, неоднозначных названий и независимости выбора от последней карточки.

Вопросы о времени поддерживаются через discuss/cooking_time, с источником и явным отсутствием неизвестного времени.
